# YouTube / TikTok publishing boundary v1
Approved direction: extend existing Channels/Posts, preserve English UI, current accounts and shared Hub callbacks. No per-product logic, no paid video generation. First tests use existing15second video, destination Joshua Wan; visibility awaits explicit user choice.

1. OAuth: default identity-only unchanged. Owner explicitly chooses Enable publishing, sending signed purpose=publish to Hub. Hub binds purpose to encrypted transaction and requests identity+youtube.upload or identity+video.publish, never caller-supplied arbitrary scopes. Denial retains existing account. Tokens encrypted, no callback changes. Before live grant expansion get action-time user approval / consent handoff.
2. YouTube: resumable upload session persisted before bytes; query known session on uncertain transfer, no new session/repeated upload automatically. Title, description, explicit visibility, made-for-kids and synthetic-media disclosure. notifySubscribers=false for test. Status verified by returned video ID. Existing identity scope remains for channel checks.
3. TikTok: DirectPost already enabled in Live app, video.publish andvideo.upload listed. Use video.publish only for first direct test. Creator-info preflight; current returned privacy options, manually selected with no default, interaction options off unless user chooses; disabled options enforced; title editable; commercial disclosure and required music/policy acknowledgement. Final legal acknowledgement/user approval must occur at action time. Use FILE_UPLOAD for video to avoid changing client domain verification. Persist publish_id/upload URL before bytes, URL tightly allowlisted; status polling known publish_id only. No silent draft-upload fallback.
4. Production app audit status/creator API determines visibility; private test is not proof of public publishing approval. Existing app scopes don't prove current token grants. Failed/unknown don't resend.
5. Fake acceptance first: intent binding, no scope expansion for ordinary connect, wrong actor/client/account denied; token refresh preserved; resumable/chunk failures reuse tasks, no duplicate submissions; platform readiness, disclosure and visibility errors. Then normal-page real consent and one test perplatform. Preserve originals/versions; release only this scope after tests and user sync authority. No arbitrary global scope upgrade.
