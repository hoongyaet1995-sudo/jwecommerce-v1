# Google AI Studio 补充：实体仓库存对账控件

请以 ZIP35 为设计来源，仅在 Marketplace Inventory & WMS 补齐以下实际业务入口，保留既有布局、色彩、组件风格与短屏弹窗规范。不要把店铺 safetyBufferPercent 当作实体仓 safetyStock 数量。

在 SKU 展开的实体仓行增加“Reconcile Inventory”入口。弹窗绑定固定 SKU 和实体仓，显示最近盘点数量及日期、服务器计算的未出库预留数量、当前安全库存数量与 ATP。未知值显示 Pending reconciliation，禁止默认为零。未盘点先引导盘点。

允许输入非负整数的安全库存单位数、必填原因；操作人来自当前认证员工，不能自由输入或切换冒充。预留数量只读，来自订单分配明细。存在未归仓订单或未核对订单覆盖时明确展示阻塞项，不能勾选绕过。

提交前提供第二步复核：实体库存不变、预留前后值、安全库存前后值、ATP 变化、关联店铺影响。确认后调用服务器契约并等待真实回执；失败保留表单，库存版本冲突要求重新加载复核，重复点击不得重复记账。明确区分余额对账与按店开启平台写入；对账本身不能宣称已推送 Shopee/Lazada。

表单及复核步骤均沿用 ZIP35：限制视窗高度，固定标题与底部按钮，中间内部滚动。兼容 1366×768、1024×600、390×844。保留现有其他功能，不以示例成功或本地状态宣称真实持久化。

另请在模式配置区为尚未选择模式提供明确初始状态，不能显示默认已启用；模式切换结果、阻塞订单、在途调拨均由服务器返回。共享池转多仓时不得用“均分”假装货物实际分布；分配须有明确仓库数量并守恒，有未确定归属时阻止完成。
