# Wedding PDP editorial concept v1

2026-10-16. Sample only, not implemented. User asked research professional wedding service pages, avoid conventional ecommerce PDP, stay within existing backend controls. Earlier PDP choice retained: full-width panorama above package introduction. PLP horizontal-row approval does not silently replace PDP composition.

Research: https://www.gregfinck.com/about (bespoke experience and approach); https://www.josevilla.com/about (fine-art photography approach); https://ktmerry.com/faq (planning and service explanations). Inspiration only, no source photos/code copied.

- Breadcrumb: actual category/product names, canonical spaced separators.
- Panorama / gallery: Product Media ordered images; gallery lightbox uses existing gallery behavior. A still sample does not prove zoom or responsive behavior.
- Eyebrow: product Category name; hide if absent.
- Name, lead, body: Product title/subtitle/description.
- Enquiry block: actual price_display and purchase_mode; existing product/selected variant enquiry. No new scheduling or booking confirmation; optional preferred date can be described in existing requirements, not an invented date field.
- Gallery secondary photographs: remaining Product Media, hide when absent.
- Service details: editable extra-info accordion content. No hardcoded guarantees/deliverables; sample copy illustrative.
- Story: existing Product Story label, heading, description, image/alt/focus. No story CTA absent from contract.
- Related: configured pdpRelatedProducts; hide empty.
- Quote mode no cart quantity/stock/Buy Now UI. Direct purchase/display-only modes must still preserve shared purchase presentation contracts when this theme is integrated.
- All body text canonical Page Width; full-bleed images remain independent from text widths.
